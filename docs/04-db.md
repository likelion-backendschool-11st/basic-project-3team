# DB 명세서 — Dev in

- DBMS: MySQL 8.x, 엔진 InnoDB, 문자셋 `utf8mb4`, collation `utf8mb4_0900_ai_ci`
- 생성 스크립트: `backEnd/db/schema.sql`, 테스트 데이터: `backEnd/db/seed.sql`
- 설계 근거: `docs/03-db-open-questions.md`
- 테이블을 바꾸면 `schema.sql`, `seed.sql`, 이 문서를 함께 고친다.

## 공통 규칙
- PK는 `BIGINT AUTO_INCREMENT`, 이름은 `{테이블}_id`
- 시간은 `DATETIME`, 한국 시간(KST). 커넥션 풀에 `timezone: '+09:00'`을 준다.
- `created_at`은 `DEFAULT CURRENT_TIMESTAMP`, `updated_at`은 `ON UPDATE CURRENT_TIMESTAMP`로 DB가 채운다.
- 질문·답변·답글은 soft delete: `deleted = TRUE`, `deleted_at = NOW()`. 조회할 때 `deleted = FALSE` 조건을 붙인다.
- collation이 대소문자를 구분하지 않으므로 `login_id`, `nickname`, `tag.name`의 UNIQUE도 대소문자를 구분하지 않는다.

## 테이블 관계
```
member ─┬─< question >── category
        │      ├─< question_tag >── tag ──< member_tech_stack >── member
        │      ├─< answer ─< reply
        │      │     └─ question.accepted_answer_id ──> answer (0..1)
        │      ├─< question_like
        │      └─< notification
        ├─< answer_like >── answer
        ├─< member_category >── category
        ├── refresh_token (1:0..1)
        └─< report (reporter_id, processed_by)   report.target_id ─ question | answer (FK 없음)
```

## member — 회원
| 컬럼 | 타입 | NULL | 기본값 | 설명 |
|---|---|---|---|---|
| member_id | BIGINT | N | AUTO_INCREMENT | PK |
| login_id | VARCHAR(12) | N | | 로그인 아이디. UNIQUE |
| password_hash | CHAR(60) | N | | bcrypt 해시 |
| phone | VARCHAR(11) | N | | 하이픈 없는 숫자. UNIQUE |
| nickname | VARCHAR(10) | N | | UNIQUE |
| bio | VARCHAR(200) | Y | | 소개글 |
| career_years | TINYINT UNSIGNED | Y | | 경력 연차 0~50. NULL이면 경력 미등록 |
| role | VARCHAR(20) | N | `ROLE_USER` | `ROLE_USER`, `ROLE_ADMIN` |
| status | VARCHAR(20) | N | `ACTIVE` | `ACTIVE`, `BANNED`, `WITHDRAWN` |

## refresh_token — Refresh Token
| 컬럼 | 타입 | NULL | 기본값 | 설명 |
|---|---|---|---|---|
| refresh_token_id | BIGINT | N | AUTO_INCREMENT | PK |

- 재발급할 때는 쿠키의 토큰을 해시해서 `token_hash`와 비교한다.

## question — 질문
| 컬럼 | 타입 | NULL | 기본값 | 설명 |
|---|---|---|---|---|
| question_id | BIGINT | N | AUTO_INCREMENT | PK |
| member_id | BIGINT | N | | 작성자. FK → member |
| category_id | BIGINT | N | | FK → category (질문당 1개) |
| title | VARCHAR(100) | N | | 5~100자 |
| content | TEXT | N | | 마크다운 원문. 10~10,000자 |
| view_count | INT UNSIGNED | N | 0 | 조회수 (작성자 본인 조회 제외) |
| like_count | INT UNSIGNED | N | 0 | 좋아요 수. 좋아요·취소 때 같은 트랜잭션에서 갱신 |
| accepted_answer_id | BIGINT | Y | | 채택된 답변. FK → answer, UNIQUE. NULL이면 미해결 |
| accepted_at | DATETIME | Y | | 채택 시각 |
| deleted | BOOLEAN | N | FALSE | soft delete |
| deleted_at | DATETIME | Y | | 삭제 시각 |
| created_at | DATETIME | N | CURRENT_TIMESTAMP | |
| updated_at | DATETIME | N | CURRENT_TIMESTAMP | |

- CHECK: `accepted_answer_id`와 `accepted_at`은 둘 다 NULL이거나 둘 다 값이 있다.
- 인덱스: `(deleted, created_at)` 최신순, `(deleted, like_count, created_at)` 좋아요순, `category_id`, `member_id`
- 채택은 아래 조건부 UPDATE로 한다. 바뀐 행이 0개면 이미 채택된 것이다 (409 `ALREADY_ACCEPTED`).
  ```sql
  UPDATE question SET accepted_answer_id = ?, accepted_at = NOW()
  WHERE question_id = ? AND accepted_answer_id IS NULL AND deleted = FALSE
  ```
- 삭제하면 같은 트랜잭션에서 딸린 답변·답글도 `deleted = TRUE`로 바꾼다.

## question_like / answer_like — 좋아요
| 컬럼 | 타입 | NULL | 기본값 | 설명 |
|---|---|---|---|---|
| question_like_id / answer_like_id | BIGINT | N | AUTO_INCREMENT | PK |
| member_id | BIGINT | N | | FK → member |
| question_id / answer_id | BIGINT | N | | FK → question / answer |
| created_at | DATETIME | N | CURRENT_TIMESTAMP | |

- UNIQUE `(member_id, question_id)` / `(member_id, answer_id)`. 중복 INSERT는 `ER_DUP_ENTRY`를 409 `ALREADY_LIKED`로 바꾼다.
- 취소하면 행을 실제로 지운다. 좋아요 행과 대상의 `like_count`는 한 트랜잭션에서 함께 바꾼다.

| 컬럼 | 타입 | NULL | 기본값 | 설명 |
|---|---|---|---|---|
| report_id | BIGINT | N | AUTO_INCREMENT | PK |
| reporter_id | BIGINT | N | | 신고자. FK → member |
| target_type | VARCHAR(20) | N | | `QUESTION`, `ANSWER` |
| target_id | BIGINT | N | | 대상 ID (FK 없음) |
| reason | VARCHAR(20) | N | | `SPAM`, `ABUSE`, `OBSCENE`, `PRIVACY`, `OFF_TOPIC`, `COPYRIGHT`, `ETC` |
| reason_detail | VARCHAR(200) | Y | | `ETC`일 때 필수 |
| status | VARCHAR(20) | N | `PENDING` | `PENDING`, `RESOLVED`, `REJECTED` |

| created_at | DATETIME | N | CURRENT_TIMESTAMP | |

- 대상 내용은 삭제 여부와 관계없이 `question`/`answer`에서 조회한다 (`deleted` 조건을 붙이지 않는다).

## 계산 값 쿼리 참고
- 채택률: 회원의 `deleted = FALSE`인 답변 중 `question.accepted_answer_id`로 채택된 수 ÷ 전체 수 × 100. 답변이 없으면 0.
  `SUM(q.accepted_answer_id = a.answer_id)`는 채택 답변이 없는 질문에서 NULL이 되므로 `COALESCE(SUM(...), 0)`으로 감싼다.
- 답변 수·답글 수: `COUNT(*)` + `deleted = FALSE`
- 등급·뱃지: 위 집계 값으로 코드에서 계산한다 (api.md 3장).
