# DB 설계 미결 사항 — Dev in

`docs/02-requirements.md`와 `docs/api.md`를 비교해 서로 안 맞는 부분과, DB 설계에 필요한데 정해지지 않은 규칙을 정리한다.
항목이 정해지면 `docs/api.md`, `backEnd/db/schema.sql`, DB 명세서에 반영하고 이 문서에서 해당 행을 정리한다.

## 1. 요구사항 ↔ API 명세 불일치

### 용어·식별자 충돌 (DB 설계 전에 먼저 정해야 함)
| 항목 | 02-requirements.md | api.md |
|---|---|---|
| 로그인 아이디 | 아이디 8~12자, 특수기호 `_.-` (LOGIN-002, SIGNUP-001). MYPAGE-003은 "이메일(아이디)" | `email`로 로그인 |
| 로그인 실패 문구 | "아이디 또는 비밀번호가 일치하지 않습니다." | `LOGIN_FAILED`: "이메일 또는 비밀번호 불일치" |
| 회원가입 항목 | 전화번호, 비밀번호, 닉네임 (SIGNUP-004에는 아이디 중복 확인도 있음) | `email`, `password`, `nickname` (전화번호 없음) |
| 중복 확인 | 전화번호·아이디·닉네임 | `check-email`, `check-nickname`만 있음. 전화번호 중복 확인 API와 `DUPLICATE_PHONE` 코드가 없음 |
| 비밀번호 예시 | 특수기호는 `_.-`만 허용 | 예시 `password123!`에 허용되지 않은 `!`가 들어 있음 |
| 댓글 vs 답글 | 답변 아래 **답글**만, 1단계 (ANSWER-009~011) | 질문·답변 양쪽에 **댓글**(`/comments`), `COMMENT_NOT_FOUND` |
| 신고 대상 | 질문·답변 신고만 있음 | `targetType`에 `COMMENT`도 있음 |
| 추천 vs 좋아요 | 좋아요 | 추천(`ALREADY_LIKED`는 같음) |

### 규칙이 다르거나 API에 빠진 규칙
| 항목 | 02-requirements.md | api.md |
|---|---|---|
| 본인 글 좋아요 | 답변만 금지 (ANSWER-007). 질문(QUESTION-010)에는 제한이 없음 | "본인 글은 추천할 수 없다" (질문·답변 모두) |
| 신고 사유 | 7종 선택 + 기타 직접 입력 (QUESTION-011) | `reason` 자유 문자열 |
| 질문 삭제 제한 | 채택된 답변이 있으면 삭제 불가 (QUESTION-007) | 규칙도 에러 코드도 없음 |
| 채택 답변 수정·삭제 | 불가 (ANSWER-003, 004) | 규칙도 에러 코드도 없음 |
| 메인 정렬 | 인기순 = 조회순 또는 채택수 (MAIN-007) | `sort`는 `latest`, `likes`만 있음 (TODO) |
| 답변 정렬 | 채택 답변 고정 → 좋아요순 → 최신순 (ANSWER-002) | 정렬 기준 없음 |
| 조회수 | 상세 조회 시 1 증가, 목록·상세에 표시 | 응답에 `viewCount`가 없음 |
| 태그 | 선택, 최대 8개, 추천 태그 (QUESTION-004, 008) | 요청에 `tags`가 있지만 "태그 기능 포함 여부" TODO. 상세 응답에 `tags`가 없음 |
| 작성자 정보 | 닉네임 + 경력 + 등급 + 채택률 (QNA-004) | `writer`에 `memberId`, `nickname`만 있음 |
| 입력값 검증 | 제목 5~100자, 질문·답변 내용 10자 이상, 답글 1자 이상 | 길이 규칙이 없음 |
| 회원 탈퇴 | 요구사항 없음 | `DELETE /api/members/me` 있음 |

## 2. DB 설계에 필요한데 정해지지 않은 규칙

### 필드 길이·형식
| 테이블.필드 | 현재 정해진 것 | 정해야 할 것 |
|---|---|---|
| member.아이디(또는 이메일) | 8~12자, `_.-` 허용 | 이메일인지 별도 아이디인지, 대소문자 구분 여부 |
| member.비밀번호 | 8~12자, `_.-` 허용 | 영문·숫자 조합 필수 여부 (컬럼은 bcrypt 해시 60자) |
| member.전화번호 | 중복 불가 | 하이픈 포함 여부, 자릿수 |
| member.닉네임 | 중복 불가 | 최소·최대 길이, 허용 문자 |
| member.소개글 | 글자 수 제한 표시 | 최대 길이 |
| member.경력 연차·기술 스택 | 기술 스택은 태그 선택형 | 연차를 숫자로 둘지 구간으로 둘지, 기술 스택 최대 개수, 질문 태그와 같은 테이블을 쓸지 |
| question.content / answer.content / reply.content | 최소 10 / 10 / 1자 | 최대 길이 (`TEXT`와 `MEDIUMTEXT` 중 선택) |
| tag.name | 질문당 최대 8개 | 이름 길이, 미리 정한 목록인지 자유 입력인지 |
| category | 관심 카테고리, 카테고리 검색 | 카테고리 목록, 질문당 1개인지 여러 개인지 |
| report.reason | 사유 7종 + 기타 | enum과 문자열 중 선택, 기타 입력 길이, 사유를 하나만 고르는지 여러 개 고르는지 |
| notification | 답변 등록·채택 알림 | 알림 종류, 메시지를 저장할지 조회할 때 만들지 |
| 등급·뱃지 | 화면 표시 방식만 있음 | 등급 단계, 획득 조건 |

### 중복 불가 (UNIQUE)
| 대상 | 현재 정해진 것 | 정해야 할 것 |
|---|---|---|
| 아이디·전화번호·닉네임 | 중복 불가 | 탈퇴 회원의 값을 다시 쓸 수 있는지 (soft delete라 행이 남음), 대소문자를 같은 값으로 볼지 (collation) |
| question_like / answer_like | 1인 1회, 다시 누르면 취소 | 취소할 때 행을 실제로 지울지 (그러면 (회원, 대상) UNIQUE로 해결) |
| report | 같은 대상 중복 신고 불가 | 반려(`REJECTED`)된 뒤 다시 신고할 수 있는지 |
| 채택 | 질문당 1개, 취소 불가 | `question.accepted_answer_id`와 `answer.accepted` 중 무엇으로 보장할지 |
| question_tag, 관심 카테고리 | 여러 개 선택 | (질문, 태그), (회원, 카테고리) 쌍 UNIQUE |

### 삭제 정책
| 대상 | 현재 정해진 것 | 정해야 할 것 |
|---|---|---|
| 질문 | soft delete. 채택 답변이 있으면 작성자는 삭제 불가 | 관리자는 삭제할 수 있는지. 딸린 답변·답글의 `deleted`도 같이 바꿀지 |
| 답변 | 채택된 답변은 작성자가 삭제 불가 | 관리자가 지우면 질문의 해결 상태와 채택률을 되돌리는지, 딸린 답글은 어떻게 할지 |
| 답글 | 관리자 삭제 가능 | 목록에서 숨길지 "삭제된 답글입니다"로 표시할지 |
| 삭제 기록 | `deleted` boolean만 있음 | `deleted_at`, 삭제 주체(작성자/관리자) 컬럼을 둘지 |
| 회원 탈퇴 | `WITHDRAWN`, Refresh Token 삭제 | 쓴 글을 남길지, 닉네임 표시 방식, 개인정보를 지우거나 가릴지, 재가입 허용 여부 |
| 회원 정지 | `BANNED` ↔ `ACTIVE` | 기간 정지인지 영구 정지인지, 사유·처리 관리자 기록 여부 |
| 좋아요 | — | 대상 글 삭제나 회원 탈퇴 때 좋아요 행과 수를 유지할지 |
| 채택률 | 채택 답변 수 ÷ 전체 답변 수 | 삭제된 답변을 분모에 넣는지 |
| 신고 | 삭제된 대상도 내용 확인 가능 | 작성자가 먼저 지운 글에 걸린 `PENDING` 신고를 어떻게 처리할지 |
| 알림 | — | 보관 기간, 대상 글이 삭제됐을 때 알림을 남길지 |
